# FloodFund Karachi · seven-minute judge demo

Before the timer starts, open the dashboard in a fresh browser profile or use **Reset session** on a dedicated rehearsal session. Check that the simulated budget starts at PKR 2,000,000 and that PostgreSQL is reachable. See the [backup checklist](BACKUP_PLAN.md).

| Time | Click or show | Say |
| --- | --- | --- |
| **0:00–0:45** | Show the dashboard and the live/demo label. | “A municipal disaster team in Karachi needs to decide whether to release pre-agreed preparedness funds before heavy rainfall. FloodFund demonstrates a rule-triggered decision and records the reason. All funding shown today is simulated.” |
| **0:45–1:30** | Point to the forecast, funding decision, and audit areas. | “Forecast: we fetch the ECMWF AIFS run through Open-Meteo and use the next 24 complete hours. Guard: we validate the data and flag implausible inputs. Rule: the demonstration uses fresh, accepted data and a threshold of at least 80 mm. Transaction: PostgreSQL locks the session and protects the session/policy/event allocation with a unique constraint. Audit: the decision records the reason and the simulated budget before and after.” |
| **1:30–3:15** | Click **Check live forecast now** and read the actual forecast status and run time. In **Live check or demo scenario**, select **Severe storm** twice. After each click, wait for the decision and check the budget. | “This is today's provider status. Now I’m switching to a clearly labeled synthetic 96 mm storm. The first run records one simulated PKR 500,000 allocation and reduces the budget from PKR 2,000,000 to PKR 1,500,000. The second run reports the event is already allocated and leaves PKR 1,500,000.” |
| **3:15–4:15** | In **Guard test**, click **Run** for **Negative rainfall**, then **Out-of-training-range features**. Show the verdicts, reason codes, and unchanged budget. | “The negative value is rejected. The second example uses a synthetic envelope and flags extrapolation as low confidence. Both are demonstration cases and neither creates a funding allocation.” **C04 takeaway:** A guard can block malformed or flagged inputs and explain why. |
| **4:15–5:15** | In **Concept drift detection**, click **Run** for **Stable distribution**, then **Residual bias**. Show the histogram, the residual mean shift, and the budget line. | “Matching distributions are stable. In the second synthetic case, the inputs still match but the signed errors shift by +8 mm, so the monitor recommends retraining. This is an informational signal for team models and does not change the live funding rule.” **C08 takeaway:** Stable inputs can coexist with shifted errors. |
| **5:15–6:15** | In **Boardroom impact**, click **Measured**, then **What-if**, **Balanced**, and **Aggressive**. At **6:00**, state the warning below before finishing. | “Measured is unavailable because the original benchmark file is absent. The earlier record reports that all models missed the sole 80 mm reference exceedance. Under the displayed assumptions, Balanced gives a PKR 29,000,000 headline gain, and Aggressive gives a PKR 9,500,000 headline loss.” **C15 takeaway:** Assumed false-alarm costs can turn a positive what-if into a loss. |
| **6:15–7:00** | Show **Challenge scoreboard**, then the README's artifact checklist. | “The 80 mm threshold is a demonstration value. We have no validated flood skill, measured environmental benefit, or actual savings to report. The original model artifacts and single-season dataset need to be restored. Next we would validate thresholds with the municipality, replace financial assumptions, and add authentication and a production scheduler.” |

**6:00 warning to say aloud:** “Every PKR estimate on this What-if screen uses assumptions. The money is simulated, and the figures are not measured savings.”

## If the provider is down

Say “The live feed is unavailable right now” and show the displayed status or missing layer. Use **Severe storm** for the funding walkthrough, then run the labeled C04 and C08 cases and the C15 What-if presets. The synthetic flows need a reachable app and PostgreSQL. If either is down, play the rehearsal clip and describe when it was recorded.
